# 인증 및 인가 컨벤션 (Auth & Authorization)

> `matsul-front` 프로젝트의 인증 상태 관리, 페이지 접근 제어, 토큰 만료 복구 정책을 정의합니다. (로컬 참고 전용)

---

## 1. 페이지 진입 가드 (Route Guards) [S14P21B205-285]

모든 라우트는 `src/app/router.tsx`에서 정의하며, 다음 4가지 가드 컴포넌트를 조합하여 접근 권한을 제어합니다.

### 1.1 가드 컴포넌트 종류
- **`PublicRoute`**: 로그인하지 않은 사용자만 접근 가능 (예: `/login`). 로그인 상태라면 `/`로 리다이렉트합니다.
- **`ProtectedRoute`**: 인증된 사용자만 접근 가능. 비로그인 시 `/login`으로 이동합니다.
- **`OnboardingOnlyRoute`**: 온보딩을 완료하지 않은 신규 사용자만 접근 가능 (예: `/onboarding`).
- **`CompletedOnboardingRoute`**: 온보딩을 완료한 사용자만 메인 기능에 접근 가능. 미완료 시 `/onboarding`으로 이동합니다.

### 1.2 하이드레이션(Hydration) 처리
- 로컬 스토리지의 인증 상태가 복구되기 전(`hasHydrated: false`)에는 가드 단계에서 `LoadingState`를 노출하여 잘못된 리다이렉트를 방지합니다.
- 초기 로딩 처리는 `AuthInitializer`와 각 가드 컴포넌트에서 이중으로 보호합니다.

### 1.3 개발 환경 우회 (Auth Bypass)
- `VITE_DEV_AUTH_BYPASS=true` 설정 시, 개발 환경(`import.meta.env.DEV`)에 한해 실제 로그인 없이 가드를 통과할 수 있습니다.
- 이 경우 `AuthInitializer`에서 테스트용 Mock 사용자 데이터를 주입하여 런타임 에러를 방지합니다.

## 2. 사용자 정보 및 예외 처리 [S14P21B205-284]

### 2.1 불완전한 상태 처리 원칙
- **명시적 로그아웃**: 사용자 정보 조회(`me` API) 실패 시, 게스트 데이터 등을 강제로 주입하지 않고 명시적으로 `logout()`을 호출하여 세션을 초기화합니다.
- **데이터 정합성**: 온보딩 정보(`usageType` 등)가 필수인 화면에서는 정보가 없을 경우 `CompletedOnboardingRoute`를 통해 즉시 온보딩 페이지로 유도합니다.

### 2.2 동기화 정책
- `useUser` 훅은 인증 토큰이 있을 때만 동작하며, `staleTime`(기본 5분) 경과 시 백그라운드에서 데이터를 최신화합니다.
- 데이터 갱신 실패 시 사용자에게 재시도 또는 재로그인(로그아웃 후 이동) 선택지를 제공합니다.

## 3. 토큰 만료 및 복구 플로우 [S14P21B205-286]

### 3.1 자동 토큰 갱신 (Silent Refresh)
- `src/api/axios.ts`의 Response Interceptor에서 `401 Unauthorized` 에러 감지 시 동작합니다.
- **중복 요청 방지**: 여러 API가 동시에 401을 뱉을 경우, 단 하나의 갱신 요청(`refresh` API)만 보내고 나머지는 큐(`failedQueue`)에서 대기하다가 갱신 완료 후 재시도합니다.

### 3.2 복구 불가능한 상태 처리
- 리프레시 토큰이 없거나 갱신 API가 실패(401 등)할 경우:
  1. 클라이언트 스토어의 모든 인증 정보 삭제 (`logout()`)
  2. 현재 페이지 상태를 초기화하고 `/login`으로 강제 리다이렉트
  3. 무한 루프 방지를 위해 `_retry` 플래그를 사용하여 단 1회만 재시도를 허용합니다.

---

## 4. 커스텀 헤더 및 보안
- 모든 API 요청 시 `Authorization: Bearer {token}` 헤더를 자동으로 부착합니다.
- 소셜 로그인 콜백이나 초기 토큰 발급 과정 등 특정 URL은 인터셉터에서 헤더 부착을 제외하도록 예외 처리합니다.
