# 추천 파이프라인 설계 문서

## 목표
API를 통해 전달받은 후보 식당(`place_id` 리스트) 중에서, 사용자의 **단기/장기 취향 데이터**를 조합한 24차원 벡터와 식당의 특징 벡터 간 **코사인 유사도**를 비교하여 **Top 3** 식당을 반환한다.

---

## 데이터 소스

| 데이터 | 출처 | 설명 |
|---|---|---|
| 후보 식당 목록 | 백엔드 API (Redis) | 위치/영업시간 필터링 완료된 `place_id` 리스트 |
| 단기 기억 (Short-term) | 챗봇이 대화에서 추론 (0~1) | 음식 종류, 분위기, 방문 목적 3종 |
| 장기 기억 (Long-term) | `USER_MEMORY` 테이블 | 누적된 24차원 취향 벡터 |
| 유저 기본 프로필 | `USER_PREFERENCE` 테이블 | Cold Start 시 초기 벡터 생성용 |
| 식당 특징 벡터 | `PLACE_MEMORY_VECTOR` 테이블 | 리뷰 기반 정규화된 24차원 점수 |

---

## 파이프라인 단계

```
[입력]
  백엔드 → Redis → { user_id, place_ids, short_term(0~1) }

[1단계: 유저 벡터 결합]
  단기기억(3종) + 장기기억(24차원) → 가중 합산
  Final = Short * α(0.7) + Long * β(0.3)
  (단기에 없는 키는 장기 값 그대로 유지)

[2단계: 식당 벡터 로드]
  PLACE_MEMORY_VECTOR에서 후보 식당 벡터 조회

[3단계: 코사인 유사도 계산]
  cosine_similarity(유저 벡터, 식당 벡터) → 점수 산출

[4단계: Top K 추출]
  유사도 내림차순 정렬 → 상위 3개 반환
```

---

## 역할 분담

| 담당 | 역할 |
|---|---|
| **챗봇 파트** | 자연어 → 단기기억 키-값(0~1) 추출 |
| **추천 파트 (나)** | 단기+장기 벡터 결합, 코사인 유사도 연산, Top 3 반환 |
| **백엔드 파트** | 위치/영업시간 필터링 후 후보 place_id를 Redis로 전달 |

---

## 핵심 설계 결정사항

- **벡터 차원**: 24차원 (memory_key_design.md 참조)
- **단기 데이터**: 3종(cuisine, vibe, occasion)만 챗봇에서 추론
- **차원 불일치 해결**: 단기(3종) + 장기(21종 fallback) = 24차원 완성
- **Cold Start**: `USER_PREFERENCE`(연령/성별/목적) 기반 초기 벡터 할당
- **식당 벡터 원천**: `CRWL_REVIEWS`(외부) + `REVIEWS`(내부) → `PLACE_REVIEW_TAGS` → `PLACE_MEMORY_VECTOR`
- **통신**: Redis Pub/Sub (백엔드 Spring ↔ AI Python)
